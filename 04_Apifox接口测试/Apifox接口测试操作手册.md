# Apifox操作要点

## 一、基础界面与核心按钮
1. 新建接口：左上角「+」号，创建 HTTP 接口
2. 请求方式：地址栏左侧下拉选择 GET / POST / PUT / DELETE
3. 发送请求：右上角蓝色【发送】按钮
4. 响应查看：下方面板，重点查看 **状态码、响应Body、响应头、Cookies、请求耗时**
5. 保存接口：调试完成后点击保存，归入项目接口集合，方便后续复用、批量执行

## 二、HTTP 常用请求方法
### 核心4种（日常99%工作使用）
- **GET**：查询/获取资源，只读操作，不修改服务器数据
- **POST**：新增/提交资源，向服务器提交数据，改变服务端状态
- **PUT**：全量更新资源，需传入完整字段覆盖原有数据
- **DELETE**：删除服务端资源

### 进阶2种（了解即可）
- **PATCH**：局部更新资源，仅修改部分字段，比 PUT 更轻量化
- **HEAD**：仅获取响应头，无响应体，用于快速探测接口是否通

### 冷门方法（了解概念）
- OPTIONS：查询服务器支持的请求方式
- TRACE：追踪请求访问链路
- CONNECT：建立隧道代理连接

> 测试口诀：**查GET、增POST、全改PUT、小改PATCH、删DELETE**

## 三、请求标签页详细作用
### 1. 参数（Params）
- 存放 URL 后缀 `?key=value` 的查询参数
- 填写后自动拼接在 URL 末尾
- **多用于 GET 请求**

### 2. 请求头（Headers）
- 存放请求修饰信息、鉴权信息
- 常见参数：Content-Type、User-Agent、Token、Cookie
- 发送 JSON 请求时，Apifox 会自动补全：`Content-Type: application/json`

### 3. 请求体（Body）
- **GET 请求无 Body**，仅 POST/PUT/PATCH/DELETE 使用
- `form-data`：支持文本 + 文件上传，文件上传接口专用
- `x-www-form-urlencoded`：普通键值对表单，不支持文件上传
- `raw-JSON`：企业项目最主流格式，前后端分离必备
- `raw-Text/XML`：老旧项目使用，日常测试极少用

## 四、GET 与 POST 面试核心区别
1. **GET（查询）**
- 参数展示在 URL 参数栏，明文展示
- 无请求体，数据暴露在外
- 有长度限制，不支持大数据传输
- 不适合传输密码、密钥等敏感数据
- 语义只读，不会修改服务器数据

2. **POST（提交/新增）**
- 参数封装在 Body 请求体中，不展示在地址栏
- 无严格长度限制，支持大数据、文件传输
- 可传输敏感数据
- 会修改服务器数据（新增/修改）

> 注意：规范是语义约束，部分后端代码不遵守规范，测试以接口实际效果为准。

## 五、HTTP 状态码全量分类（测试必背）
### 2xx 请求成功（正常）
- 200 OK：普通请求成功（查询、登录、列表接口最常用）
- 201 Created：资源创建成功（POST新增接口专用）
- 204 No Content：请求成功，无返回内容（删除接口常用）

### 3xx 重定向（跳转）
- 301：永久重定向
- 302：临时重定向
- 304：资源未更新，读取本地缓存

### 4xx 客户端错误（测试人员排查）
- 400 Bad Request：参数错误、格式错误、JSON语法错误
- 401 Unauthorized：未登录、Token缺失、Token过期
- 403 Forbidden：已登录，但无访问权限
- 404 Not Found：接口地址不存在、URL写错
- 405 Method Not Allowed：请求方法不匹配（POST写成GET）
- 429 Too Many Requests：请求频繁，被服务器限流

### 5xx 服务端错误（开发排查）
- 500 Internal Server Error：后端代码逻辑异常（最常见）
- 502 Bad Gateway：网关错误，后端服务宕机/未启动
- 503 Service Unavailable：服务不可用、过载、维护
- 504 Gateway Timeout：接口响应超时，后端处理过慢

## 六、接口响应结果解析（测试核心工作）
1. **状态码**：快速判定请求成功/失败
2. **响应头**：服务器返回的配置信息、数据格式、Cookie
3. **响应体（Body）**：核心业务数据，重点核对code、msg、data
4. **Cookies**：会话鉴权信息，常用于保持登录状态
5. **请求耗时**：判断接口性能快慢
6. **用例执行结果**：断言成功/失败，自动化测试核心依据

## 七、Apifox 高频报错排查手册
1. 404：核对 URL 地址、端口号、接口路径是否写错
2. 401：缺少 Token、Token 过期、未登录
3. 400：JSON多逗号、字段不匹配、参数类型错误
4. 405：请求 GET/POST 方法选错
5. 500：后端代码 Bug，测试复现提 Bug 单
6. 502/503：后端服务挂了、未启动、服务器异常
7. JSON 请求失败：必须选择 raw → JSON 格式

## 八、标准单接口测试流程
1. 填写正确接口地址、选择对应请求方式
2. 根据接口文档填写 Params / Headers / Body 参数
3. 发送请求，查看 HTTP 状态码
4. 校验响应体数据：字段、内容、状态是否符合需求
5. 正常则记录接口信息；异常则整理报错信息、提交缺陷
6. 保存接口，方便后续回归测试
