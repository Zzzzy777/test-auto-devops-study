# 测试计划

## 1. 测试目标

验证 RuoYi 用户管理模块的核心功能、异常校验、接口数据一致性和自动化回归能力，为后续 CI 和性能测试提供稳定入口。

## 2. 测试范围

### 功能范围

- 管理员登录
- 用户新增
- 用户查询/搜索
- 用户编辑
- 用户删除
- 重复用户名和必填字段校验

### 非功能范围

- UI/API 自动化回归
- 接口基础性能基线
- 报告、日志和失败截图留存
- Jenkins headless 执行

## 3. 测试策略

| 层级 | 工具 | 重点 |
|---|---|---|
| UI | Playwright + pytest | 真实页面流程、弹窗、表格和提示信息 |
| API | Requests + pytest | 快速验证状态码、业务码、数据生命周期 |
| 数据 | API 清理/MySQL 辅助 | 防止测试数据污染，必要时核对落库结果 |
| 性能 | JMeter | 登录和用户列表接口吞吐、响应时间、错误率 |
| CI | Jenkins | 自动安装、执行、归档和回归 |

## 4. 通过标准

- 核心 UI/API 用例全部通过
- 新增、编辑、删除用例执行后无测试用户残留
- API 响应 HTTP 状态码正常且业务 `code=200`
- 性能基线阶段无明显错误，响应时间和吞吐量记录在报告中
- Jenkins 能生成 JUnit、Allure、日志和失败截图

## 5. 风险与控制

- 环境数据被其他人修改：使用唯一用户名，不依赖固定列表行
- 弹窗/页面加载不稳定：使用显式等待和业务元素断言
- 测试失败污染数据：在 `finally` 中调用清理接口
- 密码泄露：使用环境变量或 Jenkins Credentials
- 性能测试影响环境：先小并发基线，再逐步加压并提前约定时间窗口
