# 缺陷报告示例

> 下面是一份可用于面试讲解的缺陷记录模板。真实缺陷必须以实际复现结果为准，不要把模板内容冒充线上缺陷。

## BUG-USER-001：重复用户名提交后页面提示与结果状态不一致

- **模块**：系统管理 / 用户管理
- **严重程度**：一般（需根据实际业务影响调整）
- **优先级**：高
- **环境**：RuoYi 测试环境，Chrome，Windows
- **前置条件**：系统中已存在用户名 `test_xxx`
- **复现步骤**：
  1. 登录后台并进入用户管理。
  2. 点击新增，输入已存在的用户名。
  3. 填写其他必填字段并提交。
- **预期结果**：页面明确提示用户名已存在，新增弹窗保持打开或提交失败状态。
- **实际结果**：如果前一次新增成功的 Toast 尚未消失，自动化脚本可能误把旧 Toast 当成当前操作成功。
- **定位思路**：提交前清理/等待旧提示；提交后先验证弹窗关闭，再读取当前业务提示；同时用列表查询确认最终结果。
- **修复/测试改进**：在 Page Object 中封装业务结果判断，重复用户名场景增加反向断言，测试数据使用唯一前缀。

## 缺陷记录要求

每条真实缺陷至少包含：环境、前置条件、步骤、预期、实际、严重程度、截图/日志、复现次数和修复验证结果。
