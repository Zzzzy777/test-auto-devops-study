# 03 用户CRUD完整流程自动化实战（httpbin模拟接口）
## 一、实验目的
1. 搭建完整业务链路自动化：登录→查询列表→新增用户→修改用户→删除用户
2. 掌握环境变量实现跨接口数据传递（token、用户ID）
3. 学会全局统一请求头鉴权配置
4. 通过后置脚本模拟后端返回数据，脱离真实数据库完成业务校验
5. 掌握数组对比，校验新增、修改、删除后的列表数据变化

## 二、实验环境
工具：Apifox
模拟接口服务：httpbin.ceshiren.com
运行环境：测试环境2

## 三、整体业务流程规划
整套场景共7个接口，严格按业务顺序执行：
1. POST /post 登录接口，生成token鉴权凭证
2. GET /get 查询初始用户列表
3. POST /post 新增用户，生成随机唯一用户ID
4. PUT /put 根据用户ID修改用户信息
5. GET /get 查询修改后的用户列表，校验数据更新
6. DELETE /delete 根据用户ID删除目标用户
7. GET /get 查询删除后的列表，校验数据已移除

## 四、分步操作流程
### 1. 创建自动化场景
新建场景命名：用户管理CRUD增删改查完整自动化流程，环境选择【测试环境2】。
### 2. 统一全局鉴权配置
场景全局添加请求头：`Authorization: Bearer {{token}}`，所有接口自动携带登录凭证。
### 3. 逐个配置7条接口
1）登录接口（POST /post）
后置脚本模拟登录成功，将token存入环境变量 `pm.environment.set("token","模拟令牌")`。

2）初始列表查询（GET /get）
后置脚本模拟初始化用户数组，存入环境变量，作为基准数据。

3）新增用户（POST /post）
脚本生成随机数字作为用户ID，存入环境变量 targetUserId；
向用户数组追加新用户数据，模拟数据库新增。

4）修改用户（PUT /put）
请求体JSON中动态引用变量 `{{targetUserId}}`；
后置脚本遍历数组，匹配ID修改对应用户信息。

5）修改后列表查询（GET /get）
编写断言校验数组内目标用户信息已更新。

6）删除用户（DELETE /delete）
请求体携带 {{targetUserId}}；
脚本过滤数组，移除对应ID用户数据。

7）删除后列表查询（GET /get）
断言校验列表中不存在该用户ID，确认删除生效。

### 4. 统一后置脚本规则
每个接口均添加基础断言：状态码200、响应耗时达标；
业务接口额外增加自定义数据校验断言。

### 5. 执行场景与归档
全部接口配置完成后点击【全部保存】，一键运行整套流程；
运行结束确认全部通过后，导出HTML完整测试报告，截图保存结果页面。

## 五、核心知识点
1. 环境变量跨接口传参
    - `pm.environment.set("变量名",值)`：存储数据，全局生效
    - `pm.environment.get("变量名")`：读取存储的数据
    实现登录token、新增用户ID跨接口复用。
2. 动态变量引用
    在JSON请求体、请求头中直接使用 `{{变量名称}}`，自动读取环境变量。
3. 模拟后端返回数据
    重写 `pm.response.json()` 自定义接口返回内容，无需搭建真实后端服务即可完成业务流程测试。
4. 数组处理完成CRUD校验
    使用JS数组追加、遍历修改、过滤删除，模拟数据库数据变更，验证业务逻辑正确性。
5. 自动化流程编排
    接口执行顺序严格对应真实业务操作顺序，保证流程逻辑闭环。
6. 批量断言管理
    基础通用断言（状态码、耗时）+ 业务自定义断言（数据一致性）分层校验。
