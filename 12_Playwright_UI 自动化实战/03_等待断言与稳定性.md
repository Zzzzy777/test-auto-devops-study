# 03 等待、断言与稳定性

## 1. UI 自动化为什么会不稳定

浏览器操作是异步的。点击菜单后，页面可能正在请求接口、渲染 DOM、打开动画弹窗或刷新表格。如果测试代码只按固定时间顺序执行，就会遇到：

- 元素还没有出现就开始点击
- 元素存在但仍被遮罩层挡住
- 表格已经显示但数据还没有刷新
- 旧 Toast 和当前 Toast 混在一起
- 页面地址已经变化，但业务元素尚未准备好

稳定性设计的核心是：**等待业务状态，而不是等待固定时间**。

## 2. Playwright 自动等待

对 Locator 执行操作时，Playwright 会自动等待元素满足可操作条件，包括：

1. 元素已经挂载到 DOM
2. 元素处于可见状态
3. 元素没有被其他元素遮挡
4. 元素处于稳定状态
5. 元素可用且没有被禁用

```python
button = page.get_by_role("button", name="登录")
button.click()
```

大多数情况下，不需要在点击前添加 `time.sleep(2)`。

## 3. 显式等待的正确使用

### 等待 URL

```python
page.get_by_role("button", name="登录").click()
page.wait_for_url("**/index", timeout=15000)
```

### 等待元素

```python
page.locator(".el-table").wait_for(state="visible", timeout=12000)
```

### 等待加载状态

```python
page.wait_for_load_state("domcontentloaded")
```

`networkidle` 不一定适合所有后台系统。页面可能有轮询、WebSocket 或持续请求，导致它迟迟达不到 network idle。优先等待具体业务元素。

## 4. Expect 断言会自动重试

```python
from playwright.sync_api import expect

expect(page).to_have_url(r".*/index/?$")
expect(page.locator(".user-nickname")).to_be_visible()
expect(page.get_by_text("操作成功")).to_be_visible()
expect(row).to_contain_text(username)
```

Expect 会在超时时间内反复检查结果，适合断言异步渲染的页面。

常用断言：

| 断言 | 适用场景 |
|---|---|
| `to_be_visible()` | 元素显示 |
| `to_be_hidden()` | 弹窗/遮罩关闭 |
| `to_be_enabled()` | 按钮可用 |
| `to_have_text()` | 文本完全匹配 |
| `to_contain_text()` | 文本包含 |
| `to_have_value()` | 输入框值 |
| `to_have_url()` | 页面地址 |
| `to_have_count()` | 元素数量 |

## 5. 业务结果断言要完整

不要只断言“出现了成功 Toast”：

```python
# 风险：可能读到前一次操作残留的 Toast
expect(page.get_by_text("新增成功")).to_be_visible()
```

新增用户后建议至少验证：

```text
提交按钮点击
  → 当前弹窗关闭
  → 成功提示出现
  → 搜索目标用户名
  → 表格中出现目标用户
```

重复用户名场景则相反：

```text
提交重复用户名
  → 弹窗没有被错误关闭
  → 出现当前操作对应的错误提示
  → 列表中没有多出一条重复用户
```

本项目中，`UserPage` 将弹窗状态和业务提示分开判断，避免旧 Toast 导致用例误判。

## 6. 为什么不推荐固定 sleep

```python
import time

time.sleep(3)
```

问题：

- 页面 200ms 就完成时浪费时间
- 页面 5s 才完成时仍然不够
- 失败原因不清晰
- 并发执行时更容易出现偶发失败

如果确实需要短暂等待动画，应优先等待动画结束后的元素状态：

```python
expect(page.locator(".el-dialog:visible")).to_be_visible()
expect(page.locator(".el-dialog:visible")).to_be_hidden()
```

## 7. 超时配置

项目将 UI 超时集中在 `common/config.py`：

```python
UI_TIMEOUT = int(os.getenv("RUOYI_UI_TIMEOUT", "15000"))
```

推荐层级：

- 全局默认超时：覆盖常规操作
- 页面对象超时：覆盖某一类页面
- 单个断言超时：处理特别慢的业务步骤

不要把所有超时都设置成很大。过大的超时会让真实失败等待很久，也会掩盖页面性能问题。

## 8. 调试失败流程

```powershell
pytest test_ui/test_ruoyi_user_add.py -s --headed --slowmo=600 --tb=long
```

按下面顺序排查：

1. 当前 URL 是否正确
2. 元素是否存在，匹配数量是多少
3. 元素是否可见、可用、被遮挡
4. 是否有接口请求失败
5. 断言读到的是当前结果还是旧结果
6. 测试数据是否真的创建成功
7. 清理逻辑是否执行
