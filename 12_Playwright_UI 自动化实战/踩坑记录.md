# Playwright UI自动化实战｜踩坑笔记

## 踩坑1：fixture 'page' not found
### 现象
pytest找不到page夹具
### 原因
conftest.py放在子目录，pytest不会加载子目录下的conftest
### 解决
把conftest.py放到项目根目录。

## 踩坑2：CSS类名抄写错误，明明登录成功，元素断言失败
### 现象
脚本登录成功，URL已经跳转到/index首页，但是右上角用户名断言直接失败。
### 原因
复制/手写css选择器时class名字写错。
- 页面真实class：`.user‑nickname`
- 代码错误写成：`.user‑name`，页面不存在这个类，定位直接找不到元素。

### 解决
1. 严格对照F12开发者工具里面真实class，不要凭记忆手写选择器。
2. 可以先用 `locator.wait_for()` 先等待元素，再做is_visible断言。

错误代码：
```python
assert page.locator(".user-name").is_visible(timeout=8000)
```

## 踩坑 3：strict mode violation 定位器匹配到多个元素
### 现象
playwright 执行 fill 输入时报错：`resolved to 2 elements`，无法完成输入操作。
### 原因
写了宽泛的定位表达式，页面上存在多个同类型 input 标签，定位器一次性命中 2 个 DOM 元素，Playwright 严格模式不知道操作哪一个直接抛出异常。
### 解决
1. 避免使用`input[type="text"]`这种宽泛定位；优先使用 placeholder、角色、唯一属性，保证定位器只命中 1 个元素。
2. 调试临时方案可以用`.first()`取第一个元素，正式业务用例不推荐。

错误代码：
```python
page.locator('input[type="text"]').fill("admin")
```

## 踩坑4：纯文本定位菜单匹配到多个元素
### 现象
使用`locator("text=用户管理")`点击左侧菜单，报错`resolved to 11 elements`，strict mode直接抛出异常。
### 原因
页面多处出现“用户管理”文本（左侧菜单、功能说明、列表标题、日志描述等），纯文本定位会匹配全页面所有包含该文字的元素，命中多个。
### 解决
1. 给定位器加上父容器限定范围，先定位左侧菜单`.el-menu`，再在菜单容器内查找文本。
2. 加上`exact=True`开启精确匹配，避免包含该文本的长句子也被命中。
3. 弹窗、表格内的操作同理，限定在对应容器内查找元素。

## 踩坑5：复杂CSS兄弟选择器，导致wait_for超时找不到按钮
### 现象
执行到等待新增按钮，8000ms超时，找不到元素。
### 原因
写了复杂DOM兄弟关系css选择器`.el-table__header-wrapper ~ .el-button--primary`，页面实际DOM层级和表达式不匹配，定位器匹配不到按钮。
### 解决
不要写复杂层级、兄弟选择器；优先使用`locator元素.filter(has_text="文本")`做过滤，写法简单，页面DOM小改动也不容易失效。

错误代码：
```python
add_btn = page.locator(".el-table__header-wrapper ~ .el-button--primary").filter(has_text="新增")
```

正确写法：
```python
add_btn = page.locator("button.el-button--primary").filter(has_text="新增")
```

## 踩坑6：点击新增按钮后，新增用户弹窗迟迟不弹出，弹窗wait_for超时
### 现象
成功点击新增按钮，但是等待新增用户dialog弹窗超时，10秒没有出现弹窗。
### 原因
跳转到用户管理页面之后，页面表格、后端列表接口还在请求加载，页面没有完全就绪，立刻点击新增按钮，点击事件失效，弹窗不会弹出。
### 解决
1. 进入列表页面后，使用`page.wait_for_load_state("networkidle")`等待网络空闲。
2. 等待列表表格元素渲染完成，再执行点击新增按钮操作。
3. 点击按钮之后，同样等待网络空闲，再等待弹窗出现。

> 面试要点：UI自动化不要操作太快，页面接口还在请求的时候去点击元素，会出现点击无效、弹窗不弹出这类偶现问题。

错误逻辑：
> 跳转页面 → 立刻点击新增按钮

正确逻辑：
> 跳转页面 → 等待网络空闲+等待表格渲染 → 再点击新增按钮

## 踩坑7：ElementUI下拉树悬浮层/遮罩拦截点击，报intercepts pointer events
### 现象
页面元素肉眼可见，但是click一直超时，日志提示`el‑dialog__wrapper intercepts pointer events`，弹窗遮罩层拦截鼠标点击事件。
### 原因
归属部门下拉树是挂载到body的悬浮弹窗，会和dialog弹窗遮罩层层级冲突，正常click被拦截，点不到树节点。
### 解决
对被遮挡的元素使用 `click(force=True)`，绕过页面遮罩拦截，强制触发元素点击。

>面试口述：
>force=True是兜底手段，会无视遮挡、可见性直接操作元素；正式用例不要滥用，只用于element‑ui这类组件本身层级bug的场景。

错误写法：
```python
tree.get_by_text("若依科技", exact=True).click()
```

正确写法：
```python
tree.get_by_text("若依科技", exact=True).click(force=True)
```

## 踩坑8：表单漏填必填项，弹窗直接消失，无任何错误提示
### 现象
UI自动化填写新增用户弹窗，部分必填字段漏填；点击确定，弹窗一闪直接关闭，没有弹出校验报错，后端没有新增数据，用例直接超时。肉眼看不出哪里出错。
### 根因
RuoYi‑Vue前端表单校验异常，部分场景校验失败不会弹出message提示，直接关闭dialog弹窗。
本次坑：**手机号码是新增用户的必填项，代码一开始没有填写手机号**。
### 解决
1. 做UI自动化，先在页面手动跑一遍业务，确认所有必填字段，用例全部补齐。
2. 按钮click增加force=True做兜底。

>关键点：**补上手机号**，若依新增用户接口手机号必填，漏填直接弹窗消失，没有报错提示

## 踩坑9：刷新按钮仅图标无文字，文本定位元素超时
### 现象
使用`button.filter(has_text="刷新")`定位刷新按钮，一直wait_for超时，找不到元素。
### 根因
页面刷新按钮只有图标，没有展示文字“刷新”，文本匹配定位失效。
### 解决
不要依赖页面展示文本定位图标按钮，改用class属性、元素特征定位。

>面试口述：
UI自动化不能完全依赖页面可见文本定位，很多功能按钮只有图标没有文字，会直接导致定位失败，优先使用class等属性。

## 踩坑10：测试账号手机号写死，重复运行报数据库唯一约束冲突
### 现象
用例第一次执行成功，第二次运行新增用户直接失败。
### 根因
用户名、手机号数据库设置唯一索引，脚本写死固定值，重复提交触发唯一约束报错。
### 解决
使用时间戳/uuid动态生成用户名、手机号，每次运行数据不重复。

## 踩坑11：ESC按键副作用，意外关闭新增弹窗
### 现象
执行`page.keyboard.press("Escape")`收起下拉树，偶发直接把整个新增用户dialog弹窗关闭，后续确定按钮hidden，用例超时失败。
### 根因
ElementUI Dialog默认ESC为关闭弹窗；当下拉树组件获取焦点时，ESC会同时触发收起下拉树 + 关闭弹窗两个行为。
### 错误写法
```python
tree = page.locator(".el-tree").first
tree.get_by_text("若依科技", exact=True).click(force=True)
page.keyboard.press("Escape")
```
### 解决
不再使用 ESC 按键，直接定位`vue‑treeselect`下拉菜单内部选项点击；选择完成后，等待下拉菜单完全消失，再操作弹窗内部按钮。
