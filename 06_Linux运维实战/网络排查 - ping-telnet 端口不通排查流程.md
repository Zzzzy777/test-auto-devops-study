# 网络排查｜ping、telnet，端口不通排查流程
## 实训目标
掌握网络连通分层排查思路，熟练使用 ping、telnet 工具，整理标准化端口不通排查流程，输出网络连通排查文档。

## 前置说明
- 服务：Tomcat，监听 8080 端口
- 服务端：Ubuntu 虚拟机
- 客户端：Windows（使用 CMD、telnet 工具测试）
> 核心考点：**ping 通 ≠ 端口通**
> ping 验证三层网络互通；telnet 验证四层端口连通性

## 一、基础工具实操
### 1. ping 命令
作用：测试两台机器网络是否互通（ICMP 协议）
Windows CMD 执行：
```cmd
ping 192.168.86.100
```
>现象：能收到回复代表网络互通；请求超时代表网络不通。

### 2. telnet 命令
- 作用：测试指定 IP + 端口是否连通
- Windows CMD 执行：
```cmd
telnet 192.168.86.100 8080
```

1. 连通成功：页面黑屏空白
2. 连接失败：提示「无法打开到主机的连接。 在端口 8080: 连接失败」
>telnet 退出方式：先按 Ctrl + ]，输入 quit 回车退出

## 二、端口不通 标准排查流程（固定顺序，面试必背）
1. ping 目标 IP，确认底层网络是否互通
2. 登录 Linux 服务端，执行 ss -tulpn | grep 端口号，确认服务是否正常监听端口
3. 使用 systemctl status 服务名，确认服务是否正常运行
4. 检查防火墙：ufw status，确认端口已放行
5. 查看服务日志 tail -f 日志文件，定位程序内部报错

## 三、故障模拟实操
### 故障 1：服务未启动，端口无法访问
制造故障（Ubuntu）：
```bash
cd /opt/tomcat10/bin
./shutdown.sh
ss -tulpn | grep 8080
```
>现象：无输出，8080 端口不再监听；Windows telnet 连接失败

修复方案：
```bash
cd /opt/tomcat10/bin
./startup.sh
```

### 故障 2：端口被占用，服务启动失败
制造故障（Ubuntu）：
```bash
python3 -m http.server 8080 &
ss -tulpn | grep 8080
```

排查占用进程：
```bash
lsof -i :8080
```

释放端口：
```bash
kill -9 进程PID
```

## 四、常用排查命令汇总
| 命令 | 作用 |
| ---- | ---- |
| ping ip | 测试三层网络互通 |
| telnet ip 端口 | 测试四层端口连通性 |
| ss -tulpn | 查看本机所有监听端口 |
| lsof -i :端口号 | 查看哪个进程占用指定端口 |
| systemctl status xxx | 查看服务运行状态 |
| ufw status | 查看 Ubuntu 防火墙状态 |
| tail -f xxx.log | 实时跟踪日志，定位报错 |

## 五、总结
### 端口不通四大常见原因：
1. 两端网络本身不通（ping 失败）
2. 对应业务服务没有正常启动
3. 端口被其他进程占用
4. 服务器防火墙未放行对应端口




✅ 必须掌握（面试、实操都要用，精简易懂版）
## 1. 两个测试工具区别
1. ping IP：看两台电脑网络能不能互通（能不能找到对方）
ping 通 ≠ 服务能用！只是网络通了

2. telnet IP 端口：看这个端口的服务通不通

## 2. 端口不通，固定排查顺序（背这个流程）
1）先 ping，确认网络通不通
2）进 Linux，查看端口有没有程序在监听 `ss -tulpn`
3）查看服务有没有正常启动
4）检查防火墙有没有拦住端口
5）看日志找程序报错

## 3. 3 种常见故障，看得懂、会修复
1. 服务没启动 → telnet 连不上，启动服务即可
2. 端口被别的程序占用 → 找到占用进程，杀掉释放端口
3. 防火墙拦截 → ping 正常，但端口连不上，放行端口
