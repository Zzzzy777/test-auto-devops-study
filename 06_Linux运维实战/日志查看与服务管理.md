# 日志查看与服务管理
## 1. 日志查看常用命令
### 基础tail查看日志尾部
```bash
tail syslog            # 默认查看日志末尾10行
tail -n 20 syslog      # 指定查看末尾20行
tail -n 100 syslog     # 查看末尾100行（事后排查报错常用）
tail -f syslog         # 实时监控日志新增内容，终端会卡住，Ctrl+C退出
tail -n 50 -f syslog   # 先输出最后50行，再持续实时跟踪
```

### grep 过滤日志（测试排障核心）
```bash
# -i 忽略大小写，匹配error/ERROR/Error
tail -f syslog | grep -i error

# -C 10：打印匹配行的前后各10行上下文，定位完整报错堆栈
grep -C 10 "error" /var/log/syslog

# 仅查询历史日志，不会卡住终端
tail -n 100 syslog | grep -i fail
```

>系统默认日志存放路径：/var/log/syslog

## 2. systemctl 服务管理
| 命令 | 作用 | 补充说明 |
| ---- | ---- | ---- |
| systemctl status xxx | 查看服务完整状态 | 输出运行状态、PID、最新日志，按 q 退出页面 |
| sudo systemctl start xxx | 启动服务 | 临时生效，重启机器失效 |
| sudo systemctl stop xxx | 停止服务 | 关闭当前运行的服务 |
| sudo systemctl restart xxx | 重启服务 | 修改配置后使用，中断现有连接 |
| sudo systemctl reload xxx | 重载配置 | 不中断已连接会话，仅加载新配置 |
| sudo systemctl enable xxx | 设置开机自启 | 开机自动运行该服务 |
| sudo systemctl disable xxx | 关闭开机自启 | 开机不再自动启动 |
| systemctl is-active xxx | 快速判断是否运行 | 仅输出 active/inactive，适合脚本 |
>操作系统服务需要 sudo 管理员权限

### 服务状态含义 （面试必背）
1. active (running)：绿色实心圆点，服务正常运行
2. inactive (dead)：白色空心圆点，服务已手动停止
3. failed：红色叉号，服务启动失败、程序崩溃，需要排查日志

## 3. 排障实操流程
1. systemctl status 服务名 看服务是否异常
2. tail -f /var/log/syslog | grep 服务关键词 抓取报错日志
3. 根据日志报错信息定位问题，修复后重启服务
4. 重启后再次 status 验证服务恢复正常
