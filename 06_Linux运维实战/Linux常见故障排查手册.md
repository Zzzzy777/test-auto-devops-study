# Linux常见故障排查手册
## 一、学习目标
1. 复现端口占用故障，掌握排查与解决方法
2. 复现服务配置错误启动失败故障，掌握日志定位思路
3. 形成标准化故障排查流程

## 二、故障场景1：端口占用导致服务启动失败
### 故障现象
服务启动报错 `Address already in use`，无法正常启动。

### 排查命令
1. 首选ss命令（系统自带）
```bash
ss -tulnp | grep 端口号
```
>参数说明：-t TCP、-u UDP、-l 监听状态、-n 数字端口、-p 进程信息
2. 拓展 lsof 命令
```bash
sudo lsof -i:端口号
```

### 解决方法
1. 释放端口：kill 进程PID，强制终止 kill -9 进程PID
2. 更换服务启动端口，避开占用

## 三、故障场景 2：配置错误导致服务启动失败
### 故障现象
systemctl 启动服务后状态为 failed，服务立刻退出。

### 标准排查四步走
1. 查看服务状态
```bash
systemctl status 服务名
```

2. 查看服务详细日志
```bash
journalctl -u 服务名 -n 20
```

3. 检查配置文件语法（以 nginx 为例）
```bash
sudo nginx -t
```

4. 根据报错修正配置，重启服务验证

##  四、通用故障排查流程
1. 确认服务状态：systemctl status
2. 定位报错原因：journalctl / 日志文件
3. 检查端口占用：ss -tulnp
4. 校验配置文件
5. 修复后重启验证
